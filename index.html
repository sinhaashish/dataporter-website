Product

Built for the way real file migrations actually go wrong

Large migrations rarely fail all at once — a handful of files error out, a job gets interrupted, someone needs to re-run it next week against a destination that's already half-populated. Dataporter is built around that reality instead of assuming a single clean pass.

Discovery & inventory

Walk a source file server first and get a complete, queryable inventory — file counts, sizes, and paths — before anything is copied.

Streaming transfer

Files stream from source to destination through a bounded pipe rather than being buffered whole in memory — a 200 GB file costs the same RAM as a 2 MB one.

Incremental re-sync

Re-running a migration compares size and modified time per file: unchanged files are skipped, metadata-only changes are stamped without moving data, and only real changes are copied.

Per-file fault tolerance

One bad file — a permission error, a dropped connection — doesn't stop the job. Dataporter logs it, keeps going, and reports exactly what failed and why.

Kubernetes-native worker

The transfer worker runs as an ordinary pod — no privileged mode, no kernel mounts — including against NFS exports that require a reserved source port.

Full audit trail

Every job run, every file, every retry is recorded — so a cutover decision is backed by a report, not a guess.

How it works

Four steps, start to cutover

  1. 01

    Register the source and destination

    Point Dataporter at the file servers involved — NFS or SMB shares, on-prem or cloud-hosted.

  2. 02

    Run discovery

    Inventory the source first, so you know exactly how much is about to move before it does.

  3. 03

    Migrate, with live progress

    Watch files, throughput, and any errors as the job runs — concurrent transfers, one job record per run.

  4. 04

    Re-run, verify, cut over

    Run it again closer to cutover — already-migrated files are skipped, not re-copied — then switch users to the new location with confidence.

Security & deployment

Runs inside your infrastructure, not ours

Dataporter is deployed into your own Kubernetes cluster or container environment. File data moves directly between your source and destination storage — it never transits a third-party cloud service.

  • Self-hosted by default. Runs on infrastructure you control; there's no external service in the data path.
  • No privileged containers. The transfer worker speaks the NFS protocol directly from userspace instead of requiring kernel mount capabilities.
  • Works with secured exports. Supports NFS exports that require a reserved source port, without granting the container broad host privileges.
  • Every action is logged. Job configuration, run history, and per-file outcomes are all queryable after the fact.
